# Start Project

请根据 `CLAUDE.md`、`.claude/rules` 和 `docs/project-plan.md` 启动新项目开发规划。

执行顺序：

1. 阅读 `CLAUDE.md`，理解通用规则、模型适配原则、Git 规则和项目计划书优先级。
2. 阅读 `.claude/rules` 下与当前技术栈相关的规范。
3. 阅读 `docs/project-plan.md`，提取项目目标、功能范围、暂不实现项、技术栈、数据模型、页面接口、阶段计划和验收标准。
4. 检查计划书是否存在缺失、冲突、过度工程化或范围不清的问题。
5. 根据计划书拆分开发阶段，优先生成 Phase 1 的可执行任务清单。
6. 识别需要先确认的问题。只有阻塞 Phase 1 的问题才必须提问，其余问题列为风险或后续确认项。
7. 在用户确认前，不要直接大规模改代码。

输出格式：

```txt
项目理解：
- 

计划书缺口：
- 

范围边界：
- 必须实现：
- 暂不实现：

Phase 1 任务清单：
1. 
2. 
3. 

建议目录结构：
- 

验证方式：
- 

需要确认的问题：
- 

风险与取舍：
- 
```

要求：

- 不得实现计划书明确写入“暂不实现”的功能。
- 不得因为公共规范而强行扩大项目范围。
- 如果计划书与公共规范冲突，必须指出冲突并给出推荐取舍。
- 输出必须具体到可执行任务，不要只给泛泛建议。
- 对 MiniMax-M2.7 或其他非 Claude 官方模型，必须使用明确步骤、固定输出和可验证检查项。
