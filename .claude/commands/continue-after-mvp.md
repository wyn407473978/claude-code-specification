# Continue After MVP

请在用户确认 MVP 版本后，根据 `CLAUDE.md`、`.claude/rules`、`docs/project-plan.md` 和 MVP 交付报告继续开发完整版本。

本命令只适用于 MVP Gate 已经完成，且用户明确确认可以继续的场景。目标是从 MVP 版本推进到 Final Gate。

## 执行顺序

1. 阅读 `CLAUDE.md`，确认自动执行与暂停策略。
2. 阅读 `docs/project-plan.md`，提取完整版本范围、暂不实现项、验收标准、风险和自动执行策略。
3. 阅读上一轮 MVP 交付报告或当前仓库状态，识别已完成内容、Assumptions、TODO、配置占位、未验证项。
4. 阅读与完整版本相关的 `.claude/rules/*.md` 和必要的 `.claude/agents/*.md`。
5. 将剩余问题分为两类：
   - 硬阻塞：不确认就无法继续核心功能，或涉及安全、隐私、资金、生产数据、破坏性命令风险。
   - 非阻塞信息缺口：可以继续用 Assumption、TODO、配置占位、README 待补项处理的问题。
6. 只有存在硬阻塞时，才暂停并向用户提出最小确认问题。
7. 如果没有硬阻塞，自动完成完整版本范围。
8. 开发过程中继续记录 Assumptions、TODO、占位配置、未验证项和风险，不因非阻塞信息缺口停止。
9. 完整版本实现完成后，运行可用的格式化、类型检查、测试、构建或本地启动验证。
10. 到达 `Final Gate` 后停止开发，输出最终交付报告。

## Final Gate 输出格式

```txt
最终交付报告：
-

完成范围：
-

MVP 后新增内容：
-

未包含范围：
-

Assumptions：
-

预留 TODO / 配置占位：
-

验证结果：
-

未验证项：
-

风险与取舍：
-

建议提交信息：
-

后续建议：
-
```

## 要求

- 不得实现计划书明确写入“暂不实现”的功能。
- 不得在用户确认 MVP 前执行本命令。
- 不得因为公共规范而强行扩大完整版本范围。
- 对不影响代码开发的信息缺口，必须记录并继续执行。
- 在完整版本完成前，除硬阻塞外不得频繁向用户确认。
- 完整版本完成后必须停下来，输出最终交付报告。
- 对 MiniMax-M2.7 或其他非 Claude 官方模型，必须使用明确步骤、固定输出和可验证检查项。
