# Start Project

请根据 `CLAUDE.md`、`.claude/rules` 和 `docs/project-plan.md` 启动新项目开发，并默认执行到 MVP Gate。

本命令适用于用户已经提供详细项目计划书，并希望 Claude Code 按文档自动开发的场景。除非遇到硬阻塞，不要在 MVP 完成前频繁停下来询问用户。

## 执行顺序

1. 阅读 `CLAUDE.md`，理解通用规则、自动执行与暂停策略、模型适配原则、Git 规则和项目计划书优先级。
2. 阅读 `.claude/rules` 下与当前技术栈相关的规范。
3. 如果需求可能需要多 Agent 协作，阅读 `.claude/rules/agent-teams.md` 和相关 `.claude/agents/*.md`。
4. 阅读 `docs/project-plan.md`，提取项目目标、MVP 范围、完整版本范围、暂不实现项、技术栈、数据模型、页面接口、自动执行策略、Agent Teams 策略和验收标准。
5. 检查计划书是否存在缺失、冲突、过度工程化或范围不清的问题。
6. 将问题分为两类：
   - 硬阻塞：不确认就无法继续设计核心数据模型、权限边界或主流程，或涉及安全、隐私、资金、生产数据、破坏性命令风险。
   - 非阻塞信息缺口：可以用 Assumption、TODO、配置占位、README 待补项继续推进的问题。
7. 只有存在硬阻塞时，才在开发前暂停并向用户提出最小确认问题。
8. 如果没有硬阻塞，按计划书自动实现 MVP 版本。
9. 开发过程中持续记录 Assumptions、TODO、占位配置、未验证项和风险，但不要因为非阻塞信息缺口停止。
10. MVP 实现完成后，运行可用的格式化、类型检查、测试、构建或本地启动验证。
11. 到达 `MVP Gate` 后停止开发，输出 MVP 交付报告，并等待用户确认后再进入完整版本。

## MVP Gate 输出格式

```txt
MVP 交付报告：
-

完成范围：
-

未包含范围：
-

Assumptions：
-

预留 TODO / 配置占位：
-

验证结果：
-

未验证项：
-

风险与取舍：
-

建议提交信息：
-

下一步：
- 等待用户确认 MVP。
- 用户确认后，使用 /continue-after-mvp 继续完整版本开发。
```

## 硬阻塞暂停格式

```txt
暂停原因：
-

已完成：
-

阻塞点：
-

最小确认问题：
-

可选方案：
-
```

## 要求

- 不得实现计划书明确写入“暂不实现”的功能。
- 不得因为公共规范而强行扩大 MVP 范围。
- 如果计划书与公共规范冲突，必须指出冲突并给出推荐取舍。
- 对不影响代码开发的信息缺口，必须记录并继续执行。
- 在 MVP 完成前，除硬阻塞外不得频繁向用户确认。
- MVP 完成后必须停下来，等待用户确认后才能继续完整版本。
- 对 MiniMax-M2.7 或其他非 Claude 官方模型，必须使用明确步骤、固定输出和可验证检查项。
